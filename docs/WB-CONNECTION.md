# Подключение WB: тайм-ауты и отказ в доступе

`WB не ответил (Финансы): ConnectTimeout` означает, что сервер платформы не установил соединение с финансовым API WB за отведённое время. Это само по себе не доказывает ошибку ключа. Возможны проблемы сети сервера, DNS, исходящего HTTPS, прокси или временная недоступность WB.

## Как работает исправленная проверка

Платформа проверяет срок и необходимые разделы ключа, затем параллельно обращается к четырём API WB: статистика, контент, аналитика и финансы. Это только GET /ping. При ConnectTimeout/ConnectError предусмотрена одна дополнительная попытка через 250 мс: иногда новое соединение проходит сразу после неудачного. Ответы HTTP, включая 401/403, 429 и 5xx, а также ошибки чтения/записи не повторяются.

Тайм-аут установки соединения — 3 секунды на попытку, чтения — 4 секунды. Повтор не начинается, если с учётом паузы и ещё 3 секунд на соединение он не помещается в окно 7 секунд от начала проверки раздела. Это ограничение повторов, а не абсолютный срок всего HTTP-запроса: системное разрешение DNS и отдельные этапы запроса могут занять больше времени. Диагностика показывает фактическое число попыток (`attempts`). Без успешного подтверждения WB один повтор не делает ключ действительным.

- Если WB подтвердил ключ хотя бы в одном разделе, а другие не ответили, вернули 429, 5xx или неожиданный ответ, магазин сохраняется с предупреждением. Оно перечисляет непроверенные разделы. Это не подтверждение загрузки их данных.
- Если WB явно отказал в доступе с HTTP 401/403, сохранение блокируется. Проверьте срок, права, отзыв ключа и ограничения доступа с сервера. 403 может быть связан и с сетью, поэтому не перевыпускайте ключ автоматически.
- Если ни один раздел не подтвердил ключ, магазин не создаётся. При замене ключа прежний ключ сохраняется. Ошибка сообщает, что новый ключ не проверен.
- Просроченный, тестовый ключ или ключ без необходимых разделов отклоняется до запросов к WB.

После подключения откройте «Статус обновления». Успешное добавление магазина ещё не означает, что финансы и остальные данные загружены. Не используйте пустые разделы как нулевые показатели.

## Проверка сети без передачи ключа

Из корня проекта на основном сервере, от пользователя приложения:

```bash
.venv/bin/python -m stometric.wb_probe
```

Команда не читает .env, не принимает ключи и не показывает заголовки или тела ответов. Она обращается к тем же четырём адресам без авторизации. HTTP 401/403 в этом режиме означает, что HTTP-ответ получен; он не подтверждает доступ конкретного магазина. `timeout`/`connection_error` требуют проверки DNS, исходящего порта 443, маршрута и прокси в окружении самого сервиса. Результат внутри ограниченной среды Codex не доказывает, что такое же ограничение есть у работающего сайта: сравните с запуском администратором в обычной среде сервиса.

Не отключайте TLS, firewall или sandbox целиком. Не передавайте токен в чат, аргументы shell, URL или отчёт диагностики. При ограничении источника обращайтесь к поддержке WB или хостинга. Российский VPS из RUSSIAN-SERVER.md собирает витринные цены через браузер; он не является настроенным прокси для Seller API. Ключи магазина туда не переносите.

## Обновление существующей установки

Сохраните резервную копию базы и текущего кода. Обновите исходники, сохранив локальные настройки, .env и ключ шифрования. Соберите фронтенд заново и перезапустите веб-службу по docs/OPERATIONS.md. Для этой правки публичной сборки новая схема БД не нужна. Обновите страницу браузера и повторите подключение через сайт; если магазин уже появился, используйте его, не создавайте дубликат.

Проверки без реальных ключей:

```bash
.venv/bin/python -m unittest discover -s tests -p test_wb_connection.py -v
```
