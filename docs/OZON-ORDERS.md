# Ozon: сумма заказов до и после соинвеста

В «3#Дашборд», Version2 «По дням / По неделям / По месяцам» и на Главной доступны отдельные суммы по отправлениям:

- С учётом скидки продавца: сохранённая цена продавца × количество.
- С учётом скидки продавца и соинвеста Ozon: цена покупателя из заказа × количество.
- Полнота цен покупателей: доля товаров с известной рублёвой ценой в загруженных отправлениях, взвешенная по количеству.

Обе суммы по отправлениям используют дату заказа МСК и включают отменённые заказы. Прежняя сумма «Заказано на сумму (аналитика Ozon)» сохранена отдельно: она может отличаться из-за состава данных и времени обновления. Прибыль, налоги и ДРР сохраняют прежние формулы.

Условный пример: два товара по цене продавца 1 000 ₽, цена покупателя 800 ₽. Строки покажут 2 000 ₽ и 1 600 ₽, полнота 100%. Если цена покупателя одного товара отсутствует, итог после соинвеста останется пустым, полнота будет 50%. Подтверждённый ноль отличается от отсутствующей цены. На Главной отсутствие показывается как «Нет данных», без придуманного изменения относительно прошлого дня.

Цена читается из `oz_postings.raw.financial_data.products[].customer_price`, сопоставление по SKU (в старом формате — `product_id`), без зависимости от порядка товаров. Поддержаны число/строка с `customer_currency_code` и объект `amount/currency`. Прочие валюты не пересчитываются без курса; если цена или валюта неизвестна, неполная сумма не выдаётся за итог. Указанная цена включает скидки, переданные Ozon; из неё нельзя отдельно выделить каждый вид скидки или гарантировать отдельный учёт банковской программы.

Текущая витрина, средний процент соинвеста и баллы финансового отчёта для пересчёта заказов не используются. Последние относятся к продажам и другим датам. Дополнительные вызовы API и повторная загрузка истории для показа уже сохранённых цен не нужны. Если поле отсутствует в данных установки, оно не восстанавливается предположением: нужен ответ Ozon с ценой покупателя.

Обновите исходники, соберите интерфейс и перезапустите приложение штатным способом. Версия кэша обновляется только для изменённых представлений (общий ключ Главной затрагивает её у всех площадок). Новые ключи и изменение тарифов не требуются.

Проверки: 10 числовых сценариев в `tests/test_ozon_order_prices.py`, React-сценарий `tools/frontend/ozon_order_prices.cjs` (development/production), TypeScript/Vite. Сравнение проводится по искусственным заказам FBO/FBS, отменам, разному порядку товаров, валютам, отсутствующим ценам, нулям, группам и периодам. Отдельно проверен SQL на одноразовой PostgreSQL. Это не подтверждает полноту заказов конкретного магазина: её проверяйте в своей установке.
