# Правила работы с самостоятельной установкой

Читайте README.md и docs/INSTALL.md перед изменениями. Проверяйте действующую ветку, незакоммиченные изменения и границы задания. Результат каждой работы: сделано → проверено → исправлено → перепроверено; фиксируйте реальные ограничения.

- Секреты вводит владелец скрыто или через настройки сайта. Не печатайте .env, ключи, cookie, дампы и личную историю; не добавляйте их в Git. Не копируйте чужие учётные данные.
- Соблюдайте membership и shop_ids на сервере. Поддержка и суперадмин не заменяют членство для платных ИИ-запросов. API-ключ относится к своему рабочему пространству.
- Формулы меняйте только в рамках отдельного задания с эталонными примерами. Отсутствующее значение не равно нулю; не приписывайте расчёты модели.
- Чтение WB/Ozon по умолчанию. Изменения цен, рекламы и карточек — только существующим модулем действий, после черновика и явного согласия пользователя. Не ослабляйте ограничения цены и проверки ключей.
- Перед разбором WB проверяйте восемь полных дневных отчётов точек входа. Для Ozon используйте его покрытие. Ошибку или неопределённый результат платной генерации не повторяйте автоматически.
- Проверяйте Python, реальные SQL-запросы на временной базе, TypeScript/Vite и затронутый пользовательский сценарий. Для backend импортируйте stometric.web первым. Не проверяйте миграции на чужой рабочей базе.
- Перед публикацией нужны копия, проверка staged diff, конкретный commit и приёмка после обновления. Не используйте git add -A. Не отключайте sandbox или защитные hooks. Удаление данных, смену секретов, платежи и внешние сообщения отдельно согласовывайте с владельцем.
- Используйте Claude/Codex как инструмент разработки. Не подключайте его персональную подписку как скрытый общий движок сайта; запросы сайта используют явно настроенный API.
- Локальная история и договорённости владельца относятся к закрытой документации, не к распространяемому репозиторию.
