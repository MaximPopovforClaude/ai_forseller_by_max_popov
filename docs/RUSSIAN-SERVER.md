# Второй сервер в России для витринных цен WB

Для полной схемы с витринными ценами нужны **два сервера**. Основной обслуживает сайт и хранит данные. Отдельный VPS с IP в России открывает публичные карточки WB и передаёт цены на основной сервер. Оба сервера и их обслуживание учитывайте в бюджете до аренды.

Автор платформы — Максим Попов. **Подписывайтесь на [Telegram-канал «Максим Попов. Система и масштабирование на МП»](https://t.me/maxim_popov_wb)**: работа на WB и Ozon, команда и развитие бизнеса.

## Что где работает

| Основной сервер | Российский VPS |
|---|---|
| Сайт на вашем домене, PostgreSQL, API магазинов, ИИ и Telegram | Chromium и сборщик публичной витрины WB |
| Выбирает артикулы, отправляет задание, сохраняет цены и время | Получает список артикулов, читает витрину, возвращает структурированный результат |
| Хранит настройки и ключи магазинов | Не нуждается в базе, ключах магазинов или подписке ИИ |

Связь: **основной сервер → SSH → российский сборщик → цены и время → основной сайт**. Для этой схемы второму серверу не нужен свой домен. Порт браузера наружу не публикуется.

Витринная цена показывает цену покупателя в выбранных условиях и позволяет наблюдать СПП без новых заказов. Регион, личные скидки и кошелёк могут менять видимую цену: при сравнении условия должны совпадать. IP в России сам по себе не гарантирует доступность источника.

## Что входит в репозиторий

В `infra/egress/` лежат сборщики цен `wbshow.py` и полок `wbshelf.py`, общий браузер, протокол, установщик `setup.sh` и запуск `run.sh`. На основном сервере `stometric/egress.py` принимает и проверяет результат; `showcase.py` и `shelves.py` сохраняют его штатным способом. Настройки соединения создаёт `scripts/configure_egress.py`, диагностику выполняет `scripts/egress_check.py`.

Код включён, но его нужно установить и проверить на **своих двух серверах**. Чужие адреса, ключи и данные не нужны. Сайт и API-отчёты можно запустить раньше. Плагин точек входа работает в браузере продавца и второй сервер не заменяет. Витрина Ozon этим сборщиком не поддерживается.

## 1. Подготовьте российский VPS

Нужен Linux с apt, Python 3.10+ и ресурсами для одного Chromium. Установщик рассчитан на Ubuntu 24.04. Выберите ресурсы под ассортимент и измерьте память и длительность прохода; универсальный минимум здесь не заявлен. Получите собственный административный доступ к новому VPS. Не запускайте установку на основном или чужом сервере.

На российском VPS клонируйте этот репозиторий, перейдите в его каталог и сначала посмотрите план:

```sh
git clone https://github.com/MaximPopovforClaude/ai_forseller_by_max_popov.git
cd ai_forseller_by_max_popov
sh infra/egress/setup.sh --plan
sudo sh infra/egress/setup.sh --install
```

Установщик создаёт пользователя `seller-egress`, каталог `/opt/seller-egress`, Python-окружение, Playwright с соответствующим Chromium и Xvfb. Код принадлежит root; обычный пользователь пишет только в `state/`. Если пользователь или каталог уже существуют, установка остановится для проверки. Установщик не переносит ключи, не открывает порты и не включает расписания.

Проверьте локальный запуск браузера (без обращения к WB):

```sh
printf '%s\n' '{"version":1,"kind":"probe"}' | sudo -u seller-egress /opt/seller-egress/run.sh
```

Ожидается JSON со `status: ok`, `chromium_sandbox: true`, `javascript: true`. Chromium работает от обычного пользователя с песочницей. При `browser_policy_denied` администратор должен проверить ограничения контейнера/AppArmor и разрешённый запуск установленного Chromium. Не отключайте песочницу, AppArmor или ограничения системы целиком. `display_unavailable` указывает на Xvfb, `playwright_missing` — на неполную установку зависимостей. [Установка браузера](https://playwright.dev/python/docs/browsers), [параметр chromium_sandbox](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox).

## 2. Настройте собственный SSH-доступ

На основном сервере создайте отдельный SSH-ключ для этой связи. Закрытый ключ остаётся там, вне Git; его содержимое не передавайте помощнику или в чат. Администратор российского VPS добавляет **публичную** часть в `~seller-egress/.ssh/authorized_keys`. Для этой записи используйте ограничение `restrict,command="/opt/seller-egress/run.sh"`: ключ позволяет только запуск обработчика, без оболочки, терминала и перенаправлений. Каталог `.ssh` — 700, файл — 600, владелец — `seller-egress`. Проверьте, что политика SSH позволяет вход этого пользователя по ключу; парольный вход для него не нужен.

Через консоль провайдера или администратора отдельно проверьте отпечаток ключа российского сервера. Сохраните проверенный ключ хоста в отдельный файл `known_hosts` на основном сервере. Один `ssh-keyscan` без сверки не подтверждает подлинность сервера. При нестандартном порте запись имеет вид `[host]:port`. Клиент всегда использует `StrictHostKeyChecking=yes` и собственные пути; пользовательские ProxyCommand и перенаправление агента не применяются.

## 3. Соедините основной сервер со сборщиком

Команды дальше выполняйте из каталога проекта **на основном сервере**, от пользователя приложения:

```sh
.venv/bin/python scripts/configure_egress.py
.venv/bin/python scripts/egress_check.py probe
```

Диалог спрашивает адрес, пользователя, порт, **пути** к собственному ключу и проверенному `known_hosts`, каталог сборщика и регион WB. Он не читает содержимое ключей. Параметры сохраняются в `data/egress.json` (600, исключён из Git). Существующий файл не перезаписывается: изменения проверяйте локально. По умолчанию регион `-1257786`; для сравнения цены используйте один и тот же регион на сайте WB и в настройке.

Проверьте несколько собственных товаров. Замените `YOUR_WB_ID` на числовой артикул WB; это обозначение, а не готовое значение:

```sh
.venv/bin/python scripts/egress_check.py prices YOUR_WB_ID
.venv/bin/python scripts/egress_check.py shelves YOUR_WB_ID
```

Диагностика только читает витрину, показывает цены, время, число полок, пропуски и коды ошибок; базу не меняет. Цены возвращаются в рублях, объём адаптер переводит в литры. Цена гостевая, без личного кошелька; сравнивайте одинаковые условия. Код `http_403`, `http_429`, `http_498` или `card_unavailable_or_challenge` означает остановку: не повторяйте запросы циклом и не обходите CAPTCHA. Сначала выясните доступность источника и его ограничения. Российский IP не гарантирует доступ WB.

## 4. Проверьте сохранение и включите расписание

После успешной диагностики эти команды выполнят один сбор для выбранных кодом активных WB-магазинов вашей установки и запишут результат в **вашу** базу:

```sh
.venv/bin/python -m stometric.showcase
.venv/bin/python -m stometric.shelves
```

Проверьте несколько карточек на сайте, время обновления, СПП и полки. Формулы платформы сохранены. Ответы проверяются по версии, региону, времени, составу товаров и единицам. Неполный успешный ответ сохраняет только полученные позиции; отсутствующий товар или ошибка не превращаются в нулевую цену или пустую полку. При отказе сохраняются предыдущие данные: отдельно следите за их возрастом. Отказ источника или связи завершает проход с ошибкой, без перехода к следующим порциям. Одного exit 0 недостаточно: проверьте также пропуски, журнал и свежесть в базе.

Убедитесь, что при потере SSH сайт продолжает работать, результаты не заменяются нулями; проверьте связь после перезапуска обоих серверов. Цены и полки используют один `flock`, ожидание блокировки — 60 секунд, один браузерный запуск — не более 30 минут. `Worker busy` требует дождаться текущего задания. При таймауте проверьте процессы перед повтором.

Только после этих проверок установите и просмотрите пользовательские юниты на основном сервере:

```sh
.venv/bin/python scripts/install_units.py
systemctl --user daemon-reload
systemctl --user cat ai-stometric-showcase.timer ai-stometric-shelves.timer
```

Скрипт пишет юниты, но не включает их. Шаблон: цены каждые 30 минут, полки в 23:00 UTC (02:00 МСК). Если установка уже работает, перед повторным запуском сохраните свои изменения юнитов: скрипт их перезаписывает. Проверьте нагрузку и измените расписание под свою установку, затем явно включите нужные таймеры:

```sh
systemctl --user enable --now ai-stometric-showcase.timer ai-stometric-shelves.timer
systemctl --user list-timers 'ai-stometric-*'
journalctl --user -u ai-stometric-showcase -u ai-stometric-shelves --since today
```

Для фоновой работы пользователя после выхода нужен linger; его настраивает администратор основного сервера. Без успешной приёмки таймеры оставьте выключенными. Скрипты не отключают защиту и не меняют токены магазинов.

## Обновление и восстановление

Сохраните версию Git, `data/egress.json`, проверенный ключ хоста, собственный SSH-ключ в закрытом хранилище, свои юниты и конфигурацию доступа. На российском VPS сохраните копию `/opt/seller-egress` и настроек пользователя. Это не заменяет [резервную копию основной базы](OPERATIONS.md).

Для обновления остановите свои два таймера на основном сервере и дождитесь завершения активных сборов. Сохраните прежний каталог российского сборщика. Администратор устанавливает обновлённые `*.py`, `run.sh` и `requirements.txt` из `infra/egress/`, сохраняя владельца root и права запуска; при изменении requirements пересоздаёт окружение и соответствующий браузер по шагам `setup.sh`. Не запускайте установщик поверх существующего каталога и не удаляйте прежнюю копию. Сохраните `state/` и свой SSH-доступ. Проверьте совместимость обеих версий, локальный probe, SSH-probe и несколько карточек, затем верните расписание. Для отката восстановите согласованную пару версий основного адаптера и сборщика из копий.

## Что проверено в распространяемой версии

Автономные тесты проверяют контракт цен/полок, RUB/литры, пропуски и ошибки WB, ограничения SSH, свежесть ответа, блокировку и сроки выполнения. Установщик проверен в режиме `--plan`; шаблоны расписаний проверены без запуска. Полная установка на новом VPS, реальный вход SSH и живой сбор WB **не выполнялись при подготовке этого пакета**. Их подтверждает приёмка именно вашей установки.
