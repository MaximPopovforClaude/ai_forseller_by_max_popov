# Проверки подготовленной сборки

Дата: 06.11.2026.

- Все SQL-миграции выполнены на временном PostgreSQL 16 в single-user mode. До bootstrap таблицы пользователей, магазинов, рабочих пространств, новостей, включённых ИИ-магазинов и API-ключей пусты.
- Bootstrap проверен на этой базе: новый администратор/рабочее пространство, хеш пароля, отказ при повторной инициализации.
- Реквизиты исходного оператора не заданы. На пустой базе оферта и политика не публикуются, журнал действий пуст; после bootstrap в нём только событие создания собственной установки. Эти состояния проверены реальными SQL-запросами.
- На реальных SQL-запросах проверен API-доступ: без ключа закрыт, со своим ключом и членством открыт, чужой пользователь/ограниченный shop_ids/неактивный магазин закрыты. Это не тест конкурентных транзакций.
- Проверены доступность формы первого API-ключа и запрет замены общего ключа администратором с доступом лишь к отдельным магазинам.
- Четыре этапа ИИ-задач прошли с искусственными ответами API. Реальные платные запросы не выполнялись. Частная подписка программно недоступна.
- Выполнены компиляция Python, TypeScript и сборка Vite. Сборка фронтенда использовала уже установленные зависимости; установка всех пакетов с нуля в отдельной ОС не проверена. Vite предупреждает о размере основного JS-бандла.
- Проверены пути и содержимое на известные приватные идентификаторы исходной установки, учётные данные, ключи, адреса серверов, переписку, персональные конфигурации и бинарные данные. Поддерживаемый сканер — scripts/audit_source.py. Эвристическая проверка не является независимым аудитом безопасности.
- Для 27 модулей таблиц и расчётов сравнено синтаксическое дерево с исходной реализацией после удаления приватных комментариев/описаний. Алгоритмы и числовые константы этих модулей не изменены.
- Плагин 0.2.8: реальные JS-файлы выполняются в Node с искусственными событиями Chrome и ответами WB/платформы. Проверяются изоляция сессий вкладок/документов/юрлиц, TTL, отказ 401 и ограниченный повтор, смена кабинета, ошибки этапов, границы скачивания, отсутствие секретов в диагностике и изоляция покупательского поиска WB. Реальный браузер и авторизация WB этим не проверяются.

Не проверены: новый сервер целиком, системная установка зависимостей, реальные DNS/TLS/nginx, systemd и linger на новом хосте, настоящий браузер пользователя, реальные API маркетплейсов/ИИ и восстановление пользовательского дампа. Их проверяет владелец установки по docs/ACCEPTANCE.md. Внешние браузеры витрин и частная инфраструктура исключены, что явно обозначено в README.

Воспроизведение локальных проверок из корня:

```bash
.venv/bin/python -m compileall -q stometric tools scripts tests
.venv/bin/python tests/test_installation.py -v
.venv/bin/python scripts/audit_source.py
node tools/frontend/plugin_regression.cjs
node tools/frontend/plugin_auth_regression.cjs
node tools/frontend/plugin_seller_regression.cjs
```

SQL-проверка требует установленные бинарные файлы PostgreSQL 16. Она создаёт временную базу, не читает .env и не подключается к рабочему серверу БД. Если PostgreSQL отсутствует или тест запущен от root, этот тест будет пропущен — это не успешная проверка SQL.
