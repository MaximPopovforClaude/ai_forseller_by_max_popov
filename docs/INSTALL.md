# Установка на свой сервер

При установке сохраняйте логотипы **AI-100metric by Max Popov** и подпись автора: вход, меню, обе темы, favicon и расширение. Собственный домен и реквизиты меняются отдельно. См. [айдентику платформы](BRANDING.md).

Целевая среда: Ubuntu 24.04, PostgreSQL 16, Python 3.12, Node.js и Bun, systemd пользователя, nginx и HTTPS. Устанавливайте в отдельную папку без пробелов. Команды выполняются от обычного пользователя; административные шаги отдельно выполняет владелец сервера. Docker-установка в этой версии не подготовлена.

Платформа создана Максимом Поповым. **Подписывайтесь на [его Telegram-канал «Максим Попов. Система и масштабирование на МП»](https://t.me/maxim_popov_wb)** — там он делится опытом продаж на WB и Ozon, работы с командой и развития бизнеса.

## 1. Подготовить окружение

Для полной установки с витринными ценами WB предусмотрены **два сервера**:

- Основной: сайт, PostgreSQL, сбор API, нейросеть и Telegram-бот. Домен указывает на него.
- Отдельный VPS с IP в России: браузерный сборщик витринных цен WB. Передаёт результат на основной сервер; второй домен для связи по SSH не требуется.

Учтите обе аренды до покупки. Шаги ниже устанавливают основной сервер. Подключение российского сборщика описано в [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md): код сборщика, установщик и SSH-адаптер входят в репозиторий. Одной аренды VPS недостаточно. Можно начать с API-отчётов, затем завершить витринный сбор. Плагин точек входа работает отдельно в браузере продавца.

При работе через Claude Code или Codex передайте [готовое задание на второй сервер](AI-RUSSIAN-SERVER.md): в нём установка, SSH, probe, цены и полки, сохранение на сайте, расписание и восстановление. Общее задание на оба сервера — [AI-GUIDE.md](AI-GUIDE.md).

Получите этот репозиторий через Git или распакуйте архив. Создайте виртуальное окружение в его корне:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Если venv недоступен, администратор устанавливает пакет python3-venv. PostgreSQL, nginx и сертификаты также устанавливаются администратором. Не запускайте весь сайт от root.

Установите Bun по [официальной инструкции](https://bun.sh/docs/installation). Из папки web/frontend:

```bash
bun install --frozen-lockfile
bun run build
```

Сохраните bun.lock; не обновляйте зависимости одновременно с первой установкой. После сборки вернитесь в корень проекта. Каталог dist создаётся локально и не хранится в Git.

## 2. Создать пустую базу

Рекомендуется локальный PostgreSQL и peer-аутентификация: роль базы совпадает с Linux-пользователем приложения. Администратор один раз создаёт эту роль без SUPERUSER и базу seller_analytics с ней в качестве владельца. Не используйте базу другого приложения. Для удалённой БД настройте отдельную роль, TLS и ограничение сети.

Программа настройки спросит адрес сайта и DSN скрытым вводом; пустой DSN означает локальную базу seller_analytics. Она создаст уникальный ключ шифрования, не выводя его:

```bash
.venv/bin/python scripts/configure.py
.venv/bin/python scripts/bootstrap.py
```

Первый скрипт откажется перезаписывать существующий .env. Второй применяет миграции, затем спрашивает email, название рабочего пространства и пароль администратора. Он откажется создавать начальную учётную запись, если в базе уже есть пользователи или рабочие пространства. Пароль вводится скрыто, не аргументом команды.

Не передавайте .env в чат. Храните его с правами 600; AIS_MASTER_KEY нужен для расшифровки ключей магазинов после восстановления. Он не должен меняться при рестарте или обновлении. Для проверки миграций без реальной БД есть tests/test_installation.py.

## 3. Запустить сайт и сбор данных

```bash
.venv/bin/python scripts/install_units.py
systemctl --user daemon-reload
systemctl --user enable --now ai-stometric-web.service ai-stometric-collect.timer ai-stometric-precompute.timer
```

Скрипт создаёт пользовательские unit-файлы с текущим абсолютным путём установки. Администратор включает linger для пользователя приложения, чтобы сбор продолжался после выхода из SSH. Сервис слушает только 127.0.0.1:8100.

Настройте домен и сертификат HTTPS. Пример прокси: infra/nginx.conf.example; замените домен и пути сертификата. Перед перезагрузкой nginx проверьте его конфигурацию. SITE_URL в .env должен совпадать с внешним HTTPS-адресом. Cookie входа имеет Secure, поэтому обычный HTTP не подходит для приёмки входа.

Откройте сайт, войдите созданным администратором. В «Настройках аккаунта» добавьте свой магазин WB или Ozon. Используйте ключи чтения. Для Ozon рекламный Performance API подключается отдельно от Seller API. Первая загрузка идёт в фоне; её ход виден в «Статусе обновления». Настройте себестоимость, налоги и состав артикулов.

Если при подключении WB возникает ConnectTimeout или предупреждение о непроверенных разделах, пройдите [диагностику подключения](WB-CONNECTION.md). Тайм-аут одного раздела не отменяет сохранение ключа, подтверждённого другим разделом WB; полный отказ проверки и 401/403 блокируют сохранение. После добавления отдельно проверьте загрузку данных.

Оферта и политика используют реквизиты владельца вашей установки из «Админка → Документы». Чужие реквизиты в комплект не входят; до заполнения обязательных полей документы не публикуются. Журнал действий и новости новой базы пусты. После создания первого администратора журнал содержит только событие вашей установки, затем ваши действия.

## 4. Подключить точки входа WB

В комплекте плагин **0.2.8**. Задайте ему адрес своего сервера:

```bash
.venv/bin/python scripts/configure_extension.py https://analytics.example.org
```

Здесь analytics.example.org — пример, замените своим доменом. Chrome → Расширения → Режим разработчика → Загрузить распакованное расширение → папка extension. В аккаунте сайта получите код плагина и вставьте его в окно расширения. В браузере войдите в свой кабинет продавца WB и запустите скачивание. Авторизация WB остаётся в браузере; сервер получает отчёты.

Проверьте даты и число строк в разделе «Точки входа». Для полного ежедневного разбора WB нужны восемь завершённых дней по вчера включительно. Ручная загрузка отчётов также доступна. Для другого домена повторно настройте и перезагрузите расширение.

При обновлении исходников запустите configure_extension.py заново с тем же доменом,
затем перезагрузите расширение на chrome://extensions и проверьте версию 0.2.8.
Выберите юрлицо в WB, обновите вкладку, откройте раздел «Точки входа» и нажмите
«Скачать сейчас» в плагине. Кнопка Chrome «Обновить» сама не скачивает файлы
распакованного расширения. Ошибки 401/403 и порядок обновления описаны в
[README плагина](../extension/README.md).

## 5. Включить ИИ по своему API

В «Настройках аккаунта → Нейросеть» владелец или администратор всего аккаунта выбирает провайдера, модель и вводит свой ключ. Модель должна быть доступна в вашем API-аккаунте. Ключ хранится зашифрованным, пользователи работают в пределах membership/shop_ids. Ключи OpenAI API создаются на [странице API Keys](https://platform.openai.com/api-keys); расход проверяется на [странице Usage](https://platform.openai.com/usage).

Для GPT Image есть отдельное поле «GPT Image · OpenAI API». API оплачивается отдельно от входа в Claude Code/Codex, с помощью которого вы устанавливаете платформу. Подключение API не даёт доступ к чужой подписке.

Проверьте один небольшой запрос в чате и один выбранный отчёт, прежде чем включать автоматизацию. Досье задач отправляется выбранному API-провайдеру; изучите правила обработки данных своего провайдера. Настройте доступную модель, её лимиты и контроль расходов. Большое досье может превысить контекст модели; ошибка должна сохраняться без автоматического повторения платного запроса.

Магазины ежедневных задач включаются явно из командной строки:

```bash
.venv/bin/python scripts/enable_tasks.py
systemctl --user enable --now ai-stometric-aitasks.timer
```

Таймер проверяет очередь раз в 10 минут; плановый разбор начинается с 09:40 МСК. Перед включением проверьте источники и стоимость: два анализа, объединение и проверка требуют минимум четырёх API-запросов. Для Ozon возможен один дополнительный проход исправления чисел.

## 6. Стометрик на сайте и в Telegram

Код чата, гномика, Telegram-бота и привязки уже включён. Пройдите [полную настройку Стометрика](STOMETRIC.md) или передайте [задание Claude/Codex](AI-STOMETRIC.md).

1. Выберите свой магазин, подключите API в настройках аккаунта и проверьте вопрос в пункте «Стометрик».
2. Создайте собственного бота в @BotFather, внесите токен через «Админка сервиса → Настройки → Бот Стометрика». Для него достаточно одного бота.
3. Установите юниты и запустите ai-stometric-bots.service на основном сервере. Каждый пользователь привязывает Telegram одноразовой ссылкой из своего аккаунта.
4. Проверьте /shop, ответ, историю и права. Плановые уведомления и платные фоновые ИИ-разборы по умолчанию выключены и включаются раздельно в админке после согласования.

Диагностика — scripts/check_stometric.py; команды и ограничения описаны в STOMETRIC.md. Стометрик не получает права разработчика на сервер. Личный бот разработки устанавливается отдельно и использует другой токен.
