# Свой Стометрик на сайте и в Telegram

Стометрик — помощник по магазинам: отвечает по данным платформы, показывает таблицы, помогает разбирать показатели. В репозитории есть гномик и чат сайта, серверный движок, история, Telegram-бот, привязка пользователей и плановые уведомления. Каждый экземпляр платформы использует собственные ключи и собственного Telegram-бота.

Автор — Максим Попов. **Подписывайтесь на [Telegram-канал «Максим Попов. Система и масштабирование на МП»](https://t.me/maxim_popov_wb)**: работа на WB и Ozon, команда и развитие бизнеса.

Устанавливаете через Claude Code или Codex? Передайте [готовое задание](AI-STOMETRIC.md). Основной сайт и базу сначала установите по [INSTALL.md](INSTALL.md).

## 1. Подготовьте сайт и нейросеть

1. Откройте свой сайт по HTTPS, войдите пользователем с доступом к своему магазину. Проверьте данные магазина и права в «Пользователи и права».
2. В «Настройках аккаунта → Нейросеть» владелец или администратор всего аккаунта выбирает провайдера, доступную модель и вводит свой API-ключ. Ключ шифруется общим ключом установки `AIS_MASTER_KEY`; его резервная копия обязательна. Не переносите чужие ключи и не отправляйте секреты в чат помощнику.
3. Выберите магазин и откройте пункт «Стометрик» или гномика в углу. Если гномик скрыт, в чате включите «гномик в углу». Выбор сохраняется в браузере.
4. Задайте небольшой вопрос, например: «Покажи число заказов за вчера по выбранному магазину». Сравните ответ с таблицей за тот же день. До проверки бюджетов не включайте фоновые ИИ-разборы.

Включённый в репозиторий маршрут — API своего аккаунта: одна и та же нейросеть для сайта и Telegram. Вход в Codex/Claude Code, которыми вы устанавливаете сайт, сам по себе её не подключает. Личный подписочный адаптер в этой сборке отсутствует; отдельная интеграция должна быть явно выполнена и проверена по условиям провайдера. Сторонние клиенты обслуживаются своим разрешённым API-маршрутом. Подписка автора проекта недоступна этой установке.

Полный разбор WB требует дневных точек входа за восемь завершённых дней по вчера включительно; обычный вопрос по конкретной таблице использует её доступные данные. Если источники неполные, ответ не должен выдавать отсутствие данных за нулевые показатели. Для Ozon нужны его собственные источники.

## 2. Создайте Telegram-бота своей установки

В официальном [@BotFather](https://t.me/BotFather) выполните `/newbot`, задайте имя и уникальное имя пользователя бота. Это бот Стометрика для аналитики и уведомлений. Бот-разработчик, которому разрешено изменять исходники или выкладывать сайт, создаётся отдельно и использует другой токен.

Токен вставьте на своём сайте: **«Админка сервиса → Настройки → Подключения → Бот Стометрика (Telegram)»**. Сохранение проверяет токен и показывает имя бота; токен хранится зашифрованным. Не кладите его в Git, текст инструкции или аргументы команд. Для Стометрика достаточно одного бота; отдельные боты регистрации и старых уведомлений не обязательны.

Бот использует long polling: исходящий HTTPS к Telegram, без входящего webhook-порта. Не подключайте этот же токен к другой копии сервиса или боту-разработчику. Если бот раньше работал через webhook, сначала выясните назначение прежнего подключения; отключение webhook выполняйте отдельно и явно, не удаляя его вслепую. [Получение токена](https://core.telegram.org/bots/tutorial#obtain-your-bot-token), [получение обновлений](https://core.telegram.org/bots/api#getupdates).

## 3. Запустите процесс на основном сервере

Команды выполняются пользователем приложения из каталога вашей установки. Если юниты уже создавались, сохраните свои изменения: установщик перезаписывает шаблоны. Он сам ничего не запускает.

```sh
.venv/bin/python scripts/install_units.py
systemctl --user daemon-reload
systemctl --user enable --now ai-stometric-bots.service
systemctl --user status ai-stometric-bots.service --no-pager
```

Для работы после выхода из SSH администратор должен включить linger этого пользователя. Не запускайте рядом второй `python -m stometric.bots`: процесс использует общую блокировку `data/stometric-bots.lock`. Наличие файла после остановки нормально; блокировку удерживает живой процесс. Удалять файл ради запуска второго экземпляра не нужно.

После замены токена в админке перезапустите только свой процесс ботов:

```sh
systemctl --user restart ai-stometric-bots.service
journalctl --user -u ai-stometric-bots.service --since today
```

Перезапуск может прервать текущий ответ. Дождитесь его завершения; если произошёл сбой, сначала проверьте историю и статус. Не отправляйте платный вопрос повторно автоматически.

## 4. Каждый пользователь привязывает свой Telegram

1. На сайте войдите именно в свою учётную запись.
2. Откройте «Настройки аккаунта → Стометрик и уведомления в Telegram» и нажмите «Подключить Telegram».
3. Перейдите по ссылке и нажмите Start в своём Telegram. Ссылка одноразовая, действует 30 минут; не пересылайте её другим людям.
4. Убедитесь, что на сайте появилась отметка подключения. В боте выполните `/shop` и выберите доступный магазин.

Просто открыть бота и отправить `/start` без ссылки недостаточно для новой учётной записи. Повторная привязка через новую ссылку переносит этот Telegram на выбранного пользователя сайта и убирает прежнего получателя уведомлений. Она не выдаёт доступ к новым магазинам: действуют membership, список магазинов и активность пользователя. После отзыва доступа ИИ не должен продолжать запросы к закрытому магазину.

| Команда | Действие |
|---|---|
| `/shop` | Выбрать магазин из доступных пользователю |
| `/new` | Начать новый разговор; прежняя история сохраняется |
| `/summary` | Получить сохранённую/числовую сводку выбранного магазина |
| `/summary all` | Сводка доступных включённых для уведомлений магазинов |
| `/settings` | Выбрать виды уведомлений |
| `/stop` | Выключить плановые уведомления себе; это не отмена ИИ-запроса |
| `/start` | Вернуть получение уведомлений уже привязанному пользователю |
| `/help` | Справка |

Вопросы задавайте обычным текстом. Поддерживаются фото и файлы, разрешённые движком платформы, до 10 МБ; возможности изображений/PDF зависят от выбранного API-провайдера. Telegram-разговор создаёт чат в истории этого пользователя на сайте. Новый чат сайта и Telegram не обязаны автоматически быть одним разговором; общими являются движок, доступные магазины и сохранённая история.

## 5. Включите нужные фоновые функции

В новой установке три глобальные настройки в **«Админка сервиса → Настройки»** выключены:

| Настройка | Что включает |
|---|---|
| «Стометрик: плановые уведомления» | Отправку по личным настройкам пользователей: сводки из данных, события, предупреждения и напоминания календаря |
| «Стометрик: утренние ИИ-сводки всех активных магазинов» | Утренний проход после 07:00 МСК: отчёты через настроенные API; также связанные мониторинг и фотоворонку |
| «Стометрик: плановый ИИ-разбор рекламы» | Проходы рекламы по расписанию исходного модуля, с оплатой по API; разрешения модулей сохраняются |

Сам чат и ответы на явные вопросы работают без этих переключателей. Первый переключатель не включает два платных. Ручной вопрос с ИИ всё равно расходует API. Для автоматических ИИ-разборов сначала проверьте источники, доступную модель, бюджет и состав активных магазинов. Включение утром/днём может начать текущий допустимый проход, а не ждать следующего дня. Настройка перечитывается каждую минуту; уже начатая работа сама не отменяется.

После согласия пользователей выберите личное время, окно отправки и магазины в их настройках. Время указано по Москве. Проверьте одну отправку кнопкой «Прислать сводку сейчас» и один согласованный пример календаря. Это реальные сообщения адресату; не используйте чужого получателя. `/summary` читает цифры и готовые ИИ-отчёты, не создаёт новый ИИ-разбор ради отправки.

Ежедневные «Задачи от нейросети» — отдельная очередь: выбранные магазины включает `scripts/enable_tasks.py`, запускает `ai-stometric-aitasks.timer`. Этот таймер не включается запуском Стометрика. Не дублируйте его вторым планировщиком.

## 6. Диагностика без генерации и сообщений

Скрипт читает настройки и права, не запускает ИИ, не отправляет сообщений и не показывает токены. Вместо `USER_ID` и `SHOP_ID` подставьте числовые ID пользователя и магазина своей установки из админки:

```sh
.venv/bin/python scripts/check_stometric.py --user USER_ID --shop SHOP_ID
.venv/bin/python scripts/check_stometric.py --user USER_ID --shop SHOP_ID --telegram
```

Без `--telegram` сетевых вызовов Telegram нет. С ним выполняются только `getMe` и `getWebhookInfo`; возвращается наличие webhook, но не его адрес. Нулевой код означает готовность проверенных настроек и привязки, **не факт успешного ответа ИИ**. Флаги плановой работы показаны отдельно и могут быть выключены при рабочем чате.

| Симптом | Что проверить |
|---|---|
| Гномик не виден | Выбран ли магазин; пункт «Стометрик» и галочка «гномик в углу» |
| Нет доступа к ИИ | Ключ выбранного аккаунта, доступность модели, активность пользователя/магазина, membership/shop_ids |
| Бот не настроен | Токен сохранён в админке именно этого сайта; ключ шифрования не заменён |
| Бот не отвечает | Работает ли bots.service; исходящий HTTPS; действующий токен; webhook; второй процесс с тем же токеном |
| «Ссылка устарела» | Получить новую ссылку на сайте и открыть её в нужном Telegram |
| Отвечает по другому магазину | `/shop`, доступы пользователя и выбранный аккаунт на сайте |
| Чат работает, уведомлений нет | Глобальная настройка, личные получатель/окно/время/магазины, отсутствие `/stop` |
| Не появляются ИИ-задачи | Отдельный таймер, выбранные магазины, API и полнота источников |
| Ответ прерван | Статус сообщения и журнал; автоматический повтор платного запроса не выполнять |

При диагностике не пересылайте журналы целиком: в них могут быть ваши данные. Код транспорта скрывает URL с токенами при сетевых ошибках. Защищённые конфигурации, резервные копии и локальные журналы не публикуются.

## 7. Приёмка и восстановление

Проверьте небольшой ответ на сайте и в Telegram; историю обоих каналов; выбор магазина; отказ другому пользователю; отзыв доступа до выполнения вопроса; истёкшую/повторную ссылку; сообщение и напоминание после явного включения. Дождитесь завершения запросов и проверьте работу после перезапуска процесса и выхода из SSH.

Сохраните код, базу (там история, связи и зашифрованный токен), пользовательские файлы и исходный ключ шифрования вне Git. Новый `AIS_MASTER_KEY` не расшифрует прежние токены. При пробном восстановлении выключите ботов/таймеры: две копии с одним Telegram-токеном одновременно не запускают. Порядок копий — [OPERATIONS.md](OPERATIONS.md).

Автономные тесты используют искусственные аккаунты, PostgreSQL и ответы API. Реальная отправка в Telegram, платный запрос провайдеру и новая установка проверяются владельцем на его серверах; подготовка репозитория их не заменяет.
