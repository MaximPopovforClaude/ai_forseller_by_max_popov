# Задание Claude Code или Codex: установить второй сервер

Это готовое задание для помощника с доступом к вашему репозиторию и вашим серверам. Оно одинаково подходит Claude Code и Codex. Отправьте ему текст из следующего раздела целиком. Сначала основной сайт должен быть установлен по [INSTALL.md](INSTALL.md); читать витрину для проверки можно до добавления магазина, а сохранение в платформе проверяют после его добавления.

## Готовое задание

> Установи и подключи второй, российский сервер к моей самостоятельной платформе. Результат: он читает витринные цены и полки WB, основной сервер получает и сохраняет их, я вижу свежие данные на своём сайте. Код уже есть в репозитории; используй его. Выполняй цикл «сделал → проверил → исправил → перепроверил». Не объявляй задачу готовой только по успешной установке пакетов.
>
> **1. Проверь исходное состояние.** Прочитай AGENTS.md, CLAUDE.md, README.md, docs/INSTALL.md, docs/RUSSIAN-SERVER.md, infra/egress/README.md, docs/ACCEPTANCE.md и docs/OPERATIONS.md. Проверь ветку, незакоммиченные изменения и версию кода. Уточни только недостающие сведения: адреса двух серверов, SSH-пользователей и порты, каталог проекта на основном сервере, домен сайта, регион WB и мои товары для проверки. Если VPS ещё нет, сначала согласуй ресурсы и бюджет; не покупай его сам. Перед командами обозначай сервер и пользователя. Не используй адреса и доступы автора платформы.
>
> **2. Зафиксируй схему и версию.** Сайт, PostgreSQL, API магазинов, ИИ и планировщик остаются на основном сервере. Российский VPS запускает только браузерный сборщик; отдельный домен, база, ключи маркетплейсов и подписка ИИ ему не нужны. Проверь ОС, Git, Python, часы и доступы обоих серверов. Установщик рассчитан на Ubuntu 24.04; если среда другая, сначала проверь совместимость. Используй один проверенный Git commit адаптера и worker на обоих серверах, сохрани его SHA. Не меняй другие проекты, пользователей или данные.
>
> **3. Установи worker на российском VPS.** Из своей копии репозитория выполни `sh infra/egress/setup.sh --plan`, проверь план, затем разрешённым административным способом `sudo sh infra/egress/setup.sh --install`. Скрипт создаёт отдельного пользователя seller-egress, /opt/seller-egress, Python-окружение, Playwright, Chromium и Xvfb. При существующем пользователе или каталоге остановись и выясни их назначение; не удаляй и не перезаписывай их ради повторной установки. Браузер должен запускаться обычным пользователем с песочницей. Проведи локальный JSON-probe из docs/RUSSIAN-SERVER.md: нужны status=ok, chromium_sandbox=true и javascript=true. При ошибке среды выясни причину; не добавляй --no-sandbox и не отключай системные защиты.
>
> **4. Настрой связь.** На основном сервере нужен отдельный SSH-ключ, на российском — доступ только пользователя seller-egress к фиксированному обработчику /opt/seller-egress/run.sh. Для публичной части ключа используй ограничение authorized_keys `restrict,command="/opt/seller-egress/run.sh"`, без оболочки и перенаправлений. Закрытый ключ остаётся на основном сервере; его содержимое не выводи и не проси в чат. Ключ хоста сверь через независимый источник, например консоль провайдера, и сохрани проверенную запись в отдельный known_hosts. Не отключай StrictHostKeyChecking. Новые секреты ввожу я сам; готовые секреты не извлекай.
>
> **5. Настрой основной сервер.** От пользователя приложения, из каталога проекта запусти `.venv/bin/python scripts/configure_egress.py`. Вводятся адрес, порт, пользователь, пути к своему ключу и verified known_hosts, каталог worker и регион WB; содержимое ключей вводить в этот скрипт не нужно. Настройки сохраняются в data/egress.json, вне Git, с правами 600. Если файл существует, проверь его локально без вывода содержимого ключей и без слепой перезаписи. Затем выполни `.venv/bin/python scripts/egress_check.py probe`. Только после успешного probe проверь режимы prices и shelves с числовыми ID нескольких моих товаров. Диагностика базу не меняет.
>
> **6. Проверь результат в платформе.** Сверь гостевые цены в рублях при одном регионе и условиях просмотра, время, пропуски, полки и объём в литрах. После добавления моего WB-магазина выполни по одному проходу `.venv/bin/python -m stometric.showcase` и `.venv/bin/python -m stometric.shelves`. Эти команды сохраняют результат для активных WB-магазинов установки, а не только диагностических товаров. Проверь записи и видимый результат на сайте, а также расчёт СПП без изменения формул. Проверку потери связи делай на тестовой конфигурации или в согласованном окне: сайт продолжает работать, старые значения не превращаются в нули, отсутствие полки не записывается как пустая полка. Проверь один браузер за раз, ошибки и срок ожидания, повторное подключение после перезапуска. После отказа 403/429/498, CAPTCHA, busy или таймаута выясняй причину; не повторяй проход вслепую.
>
> **7. Включи расписание после приёмки.** До успешных проверок оставляй таймеры выключенными. На основном сервере сохрани прежние пользовательские юниты, если они есть: scripts/install_units.py их перезаписывает. Создай юниты, выполни daemon-reload и покажи предложенное расписание: цены каждые 30 минут, полки в 23:00 UTC (02:00 МСК). По длительности прохода и ограничениям источника выбери подходящую частоту и согласуй её со мной. Затем включи только нужные ai-stometric-showcase.timer и ai-stometric-shelves.timer. Проверь linger, list-timers, журналы обоих сборщиков и свежесть данных. Один exit 0 не подтверждает полноту источников. Не включай попутно ИИ, сообщения или другие отключённые задачи.
>
> **8. Заверши передачу установки.** Проверь обновление и откат согласованной пары версий по docs/RUSSIAN-SERVER.md. Сохрани в закрытом хранилище конфигурацию, доступы, юниты и копию worker; российский VPS не заменяет резервную копию базы. В docs/LOCAL-STATUS.md запиши SHA, где что установлено, результаты проверок и что осталось непроверенным. Адреса и пути личной установки держи в закрытом журнале, секретные значения не записывай. Дай краткую памятку остановки, проверки, обновления и восстановления. Работающая витрина WB не доказывает работу витрины Ozon; плагин точек входа настраивается отдельно. Если недостаёт доступа или источник не пускает, укажи конкретную причину и следующий шаг, сохрани выполненное.

## Где лежат нужные команды и файлы

| Этап | Файлы / инструкция | Результат проверки |
|---|---|---|
| Российский VPS | `infra/egress/setup.sh`, раздел 1 в [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md) | Зависимости установлены; локальный probe запускает Chromium с песочницей |
| SSH между серверами | `stometric/egress.py`, раздел 2 в [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md) | Свой ключ и проверенный host key, фиксированная команда |
| Основной сервер | `scripts/configure_egress.py`, `scripts/egress_check.py` | SSH-probe успешен; prices/shelves возвращают проверенные данные |
| Сохранение | `stometric/showcase.py`, `stometric/shelves.py` | Свежие данные в своей базе и на сайте |
| Расписание | `scripts/install_units.py`, раздел 4 в [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md) | Нужные таймеры включены после приёмки; видны следующие запуски |
| Обновление и восстановление | [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md), [OPERATIONS.md](OPERATIONS.md) | Сохранена предыдущая версия и проверен способ возврата |

Код сборщика проверен автономными тестами; новая установка и живое чтение WB требуют проверки именно на ваших серверах. Общие проверки платформы остаются в [ACCEPTANCE.md](ACCEPTANCE.md).
