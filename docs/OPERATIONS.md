# Эксплуатация, копии и обновления

## Ежедневный контроль

Проверяйте ai-stometric-web.service, таймеры collect/precompute и «Статус обновления» каждого магазина. Отсутствие ошибок HTTP не доказывает свежесть данных. После обновления проверьте дату последнего успешного сбора, очередь пересчёта, вход и переключение вкладок. Журналы могут содержать бизнес-данные; не публикуйте их целиком.

```bash
systemctl --user status ai-stometric-web.service ai-stometric-collect.timer
journalctl --user -u ai-stometric-collect.service -n 60 --no-pager
```

Если данные отсутствуют: проверьте токен и его права на сайте, срок действия, 429/лимиты источника и плановый запуск. Не запускайте параллельно десятки одинаковых сборщиков. Прерванный платный ИИ-запрос сначала исследуйте; не повторяйте вслепую.

## Резервная копия

Если подключён [российский сборщик цен](RUSSIAN-SERVER.md), отдельно проверяйте его доступность, последний успешный проход и возраст цен на основном сайте. Отказ второго сервера не должен прерывать работу сайта или записывать нулевые цены. Цены и полки используют одну очередь браузера. Частоту проходов согласуйте после замера нагрузки и ограничений источника.

Нужны три составляющих: дамп PostgreSQL, каталог data с файлами пользователей и конфигурация с AIS_MASTER_KEY. Код и миграции храните в Git отдельно. Шифруйте копию, ограничьте доступ, держите копию вне основного сервера. Секреты и дампы не коммитьте даже в репозиторий исходников. Не храните ключ шифрования архива рядом с публичным архивом.

Для восстановления российского сборщика также сохраняйте его исходники, версии браузера, конфигурацию и расписание. Собственный ключ SSH храните отдельно от Git. Наличие российского VPS не заменяет резервную копию основной базы.

Для локальной peer-аутентификации пример создания дампа PostgreSQL 16:

```bash
umask 077
pg_dump --format=custom --file=backup.dump seller_analytics
pg_restore --list backup.dump
```

Чтение списка не является пробным восстановлением. Создайте отдельную пустую базу, восстановите туда дамп через pg_restore, затем проверьте таблицы, пользователей и доступ к копиям файлов. Делайте это на изолированной установке без активных сборщиков, ботов и платных API. Не запускайте восстановленную копию рядом с рабочими таймерами на тех же магазинах. [Документация PostgreSQL](https://www.postgresql.org/docs/16/backup-dump.html).

## Обновление

Зафиксируйте текущий commit и сделайте копию базы/файлов/конфигурации. Ознакомьтесь с изменениями миграций. Примените обновление сначала на тестовой установке, соберите фронтенд и запустите tests/test_installation.py. На рабочей установке остановите запуск новых фоновых задач, дождитесь выполняющихся, примените миграции и перезапустите веб. После успешной приёмки верните таймеры. Откат кода не отменяет миграции базы автоматически.

Браузер цен/полок устанавливается на своём российском VPS по RUSSIAN-SERVER.md. Перенос копий в S3 и бот-спасатель исходной установки не подключены; для них нужен отдельный адаптер и свои ресурсы. Платформа не пытается обращаться к инфраструктуре исходного проекта.

## Свой Стометрик

Настройка, привязка, диагностика и таблица сбоев — [STOMETRIC.md](STOMETRIC.md). Боту нужны база с историей и привязками, исходный ключ шифрования, токен своей установки и API-ключи аккаунтов. После замены токена перезапустите свой bots.service, дождавшись текущих ответов. Не запускайте две копии с одним токеном. Восстановленную тестовую базу проверяйте с выключенными ботами и таймерами.

Глобальные настройки плановых уведомлений, утренних ИИ-сводок и рекламного ИИ независимы и по умолчанию выключены. Включение чата не даёт согласия на платные автоматические разборы. Ежедневные задачи имеют отдельный таймер. При обновлении проверьте флаги, получателей и новые проверки tests/test_stometric.py; реальные сообщения отправляйте только согласованному получателю.
