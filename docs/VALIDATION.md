# Проверки подготовленной сборки

Дата: 06.11.2026.

- Все SQL-миграции выполнены на временном PostgreSQL 16 в single-user mode. До bootstrap таблицы пользователей, магазинов, рабочих пространств, новостей, включённых ИИ-магазинов и API-ключей пусты.
- Bootstrap проверен на этой базе: новый администратор/рабочее пространство, хеш пароля, отказ при повторной инициализации.
- Реквизиты исходного оператора не заданы. На пустой базе оферта и политика не публикуются, журнал действий пуст; после bootstrap в нём только событие создания собственной установки. Эти состояния проверены реальными SQL-запросами.
- На реальных SQL-запросах проверен API-доступ: без ключа закрыт, со своим ключом и членством открыт, чужой пользователь/ограниченный shop_ids/неактивный магазин закрыты. Это не тест конкурентных транзакций.
- Проверены доступность формы первого API-ключа и запрет замены общего ключа администратором с доступом лишь к отдельным магазинам.
- Четыре этапа ИИ-задач прошли с искусственными ответами API. Реальные платные запросы не выполнялись. Чужая подписка недоступна; собственный VIP описан в PERSONAL-AI.md.
- Выполнены компиляция Python, TypeScript и сборка Vite. Сборка фронтенда использовала уже установленные зависимости; установка всех пакетов с нуля в отдельной ОС не проверена. Vite предупреждает о размере основного JS-бандла.
- Проверены пути и содержимое на известные приватные идентификаторы исходной установки, учётные данные, ключи, адреса серверов, переписку, персональные конфигурации и бинарные данные. Поддерживаемый сканер — scripts/audit_source.py. Эвристическая проверка не является независимым аудитом безопасности.
- Для 27 модулей таблиц и расчётов сравнено синтаксическое дерево с исходной реализацией после удаления приватных комментариев/описаний. Алгоритмы и числовые константы этих модулей не изменены.
- Плагин 0.2.8: реальные JS-файлы выполняются в Node с искусственными событиями Chrome и ответами WB/платформы. Проверяются изоляция сессий вкладок/документов/юрлиц, TTL, отказ 401 и ограниченный повтор, смена кабинета, ошибки этапов, границы скачивания, отсутствие секретов в диагностике и изоляция покупательского поиска WB. Реальный браузер и авторизация WB этим не проверяются.

Не проверены: новый сервер целиком, системная установка зависимостей, реальные DNS/TLS/nginx, systemd и linger на новом хосте, настоящий браузер пользователя, реальные API маркетплейсов/ИИ и восстановление пользовательского дампа. Их проверяет владелец установки по docs/ACCEPTANCE.md. Код браузерного сборщика WB включён, но установка на новом VPS и живой сбор ещё требуют проверки; частная инфраструктура автора исключена.

Воспроизведение локальных проверок из корня:

```bash
.venv/bin/python -m compileall -q stometric tools scripts tests
.venv/bin/python tests/test_installation.py -v
.venv/bin/python scripts/audit_source.py
node tools/frontend/plugin_regression.cjs
node tools/frontend/plugin_auth_regression.cjs
node tools/frontend/plugin_seller_regression.cjs
```

SQL-проверка требует установленные бинарные файлы PostgreSQL 16. Она создаёт временную базу, не читает .env и не подключается к рабочему серверу БД. Если PostgreSQL отсутствует или тест запущен от root, этот тест будет пропущен — это не успешная проверка SQL.

## Российский сборщик

`.venv/bin/python tests/test_egress.py` выполняет 27 автономных проверок: протокол, цены и полки, ошибки/пропуски, единицы, SSH, таймауты, реальную конкуренцию за файловую блокировку, создание выключенных таймеров и установочный план. Нет подключения к рабочей базе, WB или VPS. Полную установку и реальную витрину проверяйте по [RUSSIAN-SERVER.md](RUSSIAN-SERVER.md); автономные тесты их не заменяют.

## Стометрик на сайте и в Telegram

`.venv/bin/python tests/test_stometric.py` — 18 проверок: оба канала выполняют реальную постановку и сохранение ответа на временном PostgreSQL 16 с искусственным API; история, чужие чаты, ограничения магазина/инструмента, отзыв доступа до ответа; одноразовые/истёкшие ссылки и перенос получателя; хранение токена зашифрованным; диагностика без вывода токена/webhook-адреса; раздельные настройки фона, запуск с одним ботом, исключение повторного слота и конкуренции за процесс; скрытие секретных URL сетевых ошибок и предел вложений. Telegram, провайдеры ИИ и реальные данные не вызываются; мок не доказывает живую доставку. В тестах SQL нужен непривилегированный пользователь и PostgreSQL 16.

TypeScript и Vite собраны. Полная проверка нового сервера, настоящего Telegram и платных API остаётся у владельца по STOMETRIC.md. Расчётные формулы не изменялись.

## Личный VIP владельца (09.11.2026)

Добавлены отдельная конфигурация владельца, тариф, официальный Codex app-server, текстовые запросы и встроенный GPT Image. Проверены реальные SQL-миграции и ограничения пользователей/магазинов, четыре этапа анализа, постановка и сохранение ответов сайта и Telegram, запрет переноса старой истории API в личный чат, отказ после отзыва прав и при непроверенной квоте. Реальный React проверяет подключение/сохранение VIP и ошибки в development и production. TypeScript/Vite собраны.

Протокол сверен с JSON Schema официального Codex CLI 0.166.0: thread/start, hooks, capabilities, лимиты, image input/output. RPC-ответы в тестах искусственные; живой вход, фактические лимиты и генерация владельца здесь не проверялись. Проверка на своей установке обязательна по PERSONAL-AI.md. Политика личного доступа исходного сервиса не переносится.

```bash

```

## Подключение плагина своей установки · 0.2.9
