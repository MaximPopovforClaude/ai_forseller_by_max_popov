# Плагин AI-100metric by Max Popov для Chrome · 0.2.9

Плагин скачивает «Точки входа» в открытом кабинете продавца Wildberries и передаёт отчёты на вашу установку платформы. Доступен на любом тарифе; нейросеть и её API-ключ не нужны. Загрузка требует роли редактора или выше в выбранном кабинете.

Плагин сохраняет оригинальный логотип **AI-100metric by Max Popov** и подпись автора. Автор проекта — Максим Попов. **Подписывайтесь на [его Telegram-канал](https://t.me/maxim_popov_wb)**: маркетплейсы, команда и развитие платформы. Правила бренда — [BRANDING.md](../docs/BRANDING.md).

## Установка из своего сайта

1. Разверните или обновите платформу по [INSTALL.md](../docs/INSTALL.md). Установка должна иметь рабочий HTTPS и свой настоящий адрес в `SITE_URL`.
2. На **своём сайте** откройте раздел «Плагин Chrome» в настройках аккаунта/пользователей и нажмите «Скачать плагин». ZIP уже содержит адрес этой установки в запросах, разрешениях Chrome и подсказке. Отдельно редактировать файлы не нужно.
3. Распакуйте архив в постоянную папку. Откройте `chrome://extensions`, включите режим разработчика, нажмите «Загрузить распакованное» и выберите папку `seller-analytics-plugin`, содержащую `manifest.json`.
4. Откройте окно расширения, проверьте **версию 0.2.9 и адрес своего сайта**. Получите код плагина в нужном кабинете этого же сайта, вставьте и нажмите «Подключить». Должны появиться имя и доступные магазины.
5. В WB выберите своё юрлицо, обновите вкладку, откройте раздел отчёта «Точки входа» и нажмите «Скачать сейчас». Проверьте даты и строки отчёта на своей платформе.

Если скачивание сообщает о `SITE_URL`, администратор должен задать настоящий публичный HTTPS-адрес установки и перезапустить сайт. Архив не берёт домен из непроверенного заголовка запроса и не подменяет отсутствующую настройку адресом автора проекта. При получении HTML вместо ZIP проверьте HTTPS-прокси: `/api/plugin/download` должен попадать в приложение.

## Обновление установленного расширения

Сначала обновите свой сайт, затем скачайте новый ZIP **именно с него**. Замените файлы в прежней папке расширения, перезагрузите его карточку на `chrome://extensions` и обновите вкладки WB. Удалять расширение и историю платформы не требуется. Не держите несколько старых копий одновременно.

При переходе на 0.2.9 введите код заново. Теперь код привязан к адресу установки и не отправляется другому сайту после изменения файлов. Можно использовать действующий код своего кабинета; если он не сохранён, получите новый. Перевыпуск кода отключает предыдущий код этого пользователя в этом кабинете.

Кнопка Chrome «Обновить» сама не скачивает файлы распакованного расширения. Git-обновление сайта также не меняет уже установленную копию в браузере.

## Установка прямо из исходников

Если используете папку `extension` из Git вместо ZIP сайта, сначала настройте её из корня проекта:

```bash
.venv/bin/python scripts/configure_extension.py https://analytics.example.org
```

Замените пример **на свой реальный HTTPS-домен**. Пример адреса не пройдёт проверку. Скрипт согласованно меняет адрес API, разрешения, подсказки и панель WB; сначала проверяет все файлы. После обновления исходников повторите настройку и перезагрузите расширение. Не вводите код в необработанную копию с `platform.example.org`.

## Как различить ошибки подключения

- **«Плагин не настроен на ваш сайт»**: загружена необработанная копия из Git. Скачайте настроенный ZIP со своей платформы или выполните шаг выше.
- **«Код плагина не принят» / 401 платформы**: проверьте сайт и выбранный кабинет, получите новый код именно там. Ключ API WB и тариф нейросети здесь не помогут.
- **«Нет соединения с …»**: проверьте, открывается ли указанный сайт, его HTTPS, разрешения расширения на этот домен и доступность `/api/plugin/me`. Запрос ограничен по времени; повторной отправки кода на другой домен нет.
- **«Сайт ответил не как платформа»**: вместо JSON пришла страница входа прокси, HTML ошибки или другой сайт. Администратору нужно проверить маршрутизацию `/api/`, HTTPS и канонический `SITE_URL`.
- **«Фон плагина не отвечает»**: перезагрузите расширение в Chrome и заново откройте окно. Проверьте ошибки service worker в карточке расширения. Не отправляйте диагностике коды, cookie или заголовки авторизации.
- **403 платформы**: проверьте членство в кабинете и права на магазины.

Запросы выполняются из фона расширения к явно указанному домену с [host permissions Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests). Открывать CORS для всех сайтов или отключать защиту браузера не нужно. Изменение разрешений хоста может потребовать подтверждения Chrome.

## Ошибки скачивания отчёта WB

Отказ **401 WB** отличается от отказа кода платформы: обновите вход в кабинет WB и саму вкладку. Плагин ждёт свежую сессию до 10 секунд и повторяет такой запрос не более одного раза. При **403 WB** проверьте права сотрудника на аналитику. При **429 / 5xx** проверьте доступность самого отчёта и повторите позже.

Пока идёт скачивание, не закрывайте вкладку и не переключайте юрлицо. Один запуск загружает до семи дней; автоматический сбор постепенно догружает последние 30 дней. Cookie и заголовки WB остаются в сессии браузера; платформа получает отчёты и диагностику без значений ключей.

Проверки ZIP, настройки домена, сообщений, сессий WB и загрузки выполняются с искусственными данными. Живые HTTPS, Chrome и вход WB конкретной установки проверяются отдельно.
